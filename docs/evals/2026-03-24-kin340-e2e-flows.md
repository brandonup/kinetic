## Implementation Notes

**Mock architecture:** Each journey uses per-route `get_supabase_client` patches. Routes with multiple table queries (e.g., documents GET, active_memory list, proposals GET) use `side_effect` table routing to correctly wire each table's chain independently.

**Key mock patterns discovered:**

- `documents.py` `upload`: `document_id = uuid4()` is generated internally — mock insert return does not control the returned ID. Capture from response, don't assert against a fixture value.
- `documents.py` `get_document_status`: queries two tables (`knowledge_base_documents` + `knowledge_bases` for RLS). Requires table-routing `side_effect`.
- `agents.py` `get_or_create_instance`: Step 0 queries `agent_definitions` (ownership check), Step 1 queries `agent_instances`. Both in one request — requires table-routing.
- `active_memory.py` list/proposals: both call `_verify_scope_ownership` (projects table) before main query. Requires table-routing.
- `agents.py` `update_instance`: `.update().eq("id").execute()` — one eq, not two.
- `documents.py` uses `get_supabase()` not `get_supabase_client()` — patch target: `app.api.routes.documents.get_supabase`.
