## KIN-299 — JWT expiry not validated

**Verdict: Approved → Done.**

`_check_jwt_claims()` in `auth.py` is correct:
- Base64url-decodes the payload without signature verification (intentional — signature verification is Supabase's job)
- Checks `exp` and `nbf` before the Supabase network call (fast fail on obvious cases)
- Fail-open on unparseable JWTs (let Supabase reject them) — acceptable pattern, explicitly documented
- No bare `except:` — exception is caught, logged implicitly via return, and Supabase rejects the token

No issues.

## KIN-301 — Framework selection injects framework when Haiku returns 'none'

**Verdict: Approved → Done.**

In `_haiku_rerank()`:
```python
chosen_id = (response or "").strip().strip('"').strip("'")
if not chosen_id:
    return candidates[0] if candidates else None

# Respect explicit "none" — reranker says no framework applies
if chosen_id.lower() == "none":
    return None
```

Correct:
- `"none"` check comes before the candidate match loop (the original bug path)
- Case-insensitive, strips quotes (handles `"none"`, `'none'`, `NONE`)
- Returns `None`, which causes `select_framework()` to return `None`, which causes L7 to stay empty
- Quote-stripping is the right defensive move given Haiku output variability

## KIN-300 — SSE stream sends done:true on persistence failure

**Verdict: Blocked. Needs rework.**

The persistence `except` block was updated to yield an error event (good), but the root cause was not fixed: `done: true` is still yielded **before** persistence runs.

The event sequence in the current code:

```
stream deltas... → done: true → (persistence attempt) → [error: persistence_failed if DB fails]
```

This means the client receives `done: true` and renders the message as complete before the assistant message is saved. If persistence fails, the client then receives an error event — but it has already rendered the "saved" state. On reload, the message is gone.

The correct sequence (per ADR-003 §9):

```
stream deltas... → (persistence succeeds) → done: true
stream deltas... → (persistence fails) → error: persistence_failed  [no done: true]
```

**Required fix:** Move `yield done: true` to after the persistence block succeeds. Remove it from inside the `try` block that wraps streaming. Structure should be:

```python
try:
    async for delta in stream_completion(...):
        full_response += delta
        yield delta event

    # ← no done: true here

except LLMAuthError: ...
except LLMError: ...
except Exception: ...

# Persist
try:
    await _run(persist user message)
    await _run(persist assistant message)
except Exception:
    logger.exception(...)
    yield error event
    return

yield done: true   # ← only after successful persistence
_dispatch_background_jobs(...)
```
